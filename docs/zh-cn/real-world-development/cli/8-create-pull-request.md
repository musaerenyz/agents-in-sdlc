筛选功能实现、指令更新、技能更新、质量保证（QA）配置文件和测试都已保存在同一分支上。现在一起审查这些更改并创建拉取请求（PR）。之前你手动合并了星级评分 PR；这次将由 **Agent Merge** 管理合并流程。

> [!NOTE]
> 通常会将功能、指令更新、技能更新和 QA 智能体拆分到几个独立 PR 中。为简化研讨会流程，本练习将筛选功能和质量工作流保留在同一对话和分支中，并通过一个 PR 提交。

在本课中，你将：

- 了解 Agent Merge 及其如何自动化合并流程。
- 检查完整的功能更改和验证证据。
- 创建筛选功能 PR。
- 仅在审查后启用 Agent Merge，并确认 PR 已合并。

## 场景

在筛选功能工作流中，你使用 Copilot 规划、实现并验证了功能。现在 Tailspin Toys 希望自动处理 PR 的后续工作，同时由开发人员控制合并授权。

## 了解 Agent Merge

**Agent Merge** 会自动处理合并拉取请求所需的剩余工作。启用后，Copilot 会解决阻止 PR 合并的问题，例如修复持续集成（CI）检查失败、处理审查意见，以及在需要时变基；随后，在存储库允许的情况下启用 GitHub 自动合并。

此前由你亲自选择 **Merge pull request**。Agent Merge 可以代为处理，但启用前仍应先审查工作并确认已准备就绪。

## 使用 Agent Merge 管理 PR

代码编写完成后，一起审查代码并创建 PR，再由 Agent Merge 处理其余流程。

1. 返回 Codespace。
2. 输入 `/agent` 打开智能体对话框。
3. 从选项列表中选择 **Default**，然后按 <kbd>Enter</kbd>。
4. 输入 `/pr create` 创建新 PR。
5. 输入 `/pr agentmerge` 启用 Agent Merge。
6. Copilot 会监视 PR 的持续集成流程。所有检查成功后，它会执行合并。
7. 确认 Copilot 显示了类似 “PR #14 was squash-merged successfully.” 的消息。

> [!IMPORTANT]
> Agent Merge 不会绕过必需的批准、分支保护、合并队列、存储库设置或权限限制。如果操作受阻，请查看报告的原因，并在存储库允许时手动完成已审查的合并。
