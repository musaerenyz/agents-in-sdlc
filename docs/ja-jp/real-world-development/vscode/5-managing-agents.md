Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。VS Code の Copilot Chat では、ツールの呼び出しやファイル編集をリアルタイムで確認できます。差分をインラインでレビューして変更を個別に採用または却下し、エディターを離れずに追加のプロンプトで作業を調整できます。

この演習では、次の内容を学習します。

- アクセシビリティ エージェントの作業をリアルタイムで監視する。
- 提案されたファイル編集をレビューして採用する。
- 作業中のエージェントにライトモードの切り替えを依頼し、ハイコントラスト モードと併せて実装する。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタムエージェントが、ハイコントラスト モードを実装しています。作業中にデザイン チームから、既定のテーマが暗すぎると感じる利用者向けにライトモードも追加したいという要望がありました。新しい会話を始める代わりに、既存のセッションに追加の指示を送り、作業範囲を広げます。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集が表示されます。ファイル編集は差分と **Keep** / **Undo** の操作付きでチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールしてツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求められたターミナル コマンドが表示されます。
3. ファイル編集が提案されたら、インラインの差分を確認します。
   - **Keep** を選択すると変更を採用します。
   - **Undo** を選択すると変更を元に戻し、エージェントにもう一度作業させます。
4. チャット上部の **Files changed** を開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナル コマンドの実行などで許可が必要な場合、エージェントは作業を一時停止して **Allow** を表示します。実行してもよいコマンドだけを許可してください。

5. エージェントがハイコントラスト モードの実装を終えるまで待ちます。最後に変更内容の概要が表示されます。

## ライトモードを追加するようエージェントを導く

ハイコントラスト モードができたら、同じ会話でライトモードの切り替えを追加します。会話を続けることで、エージェントは前の作業で変更した component、スタイルの方法、local storage のパターンを引き継げます。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントが既存の変更を確認し、ライトモードの追加を提案することを確認します。
3. 変更ごとに差分をレビューし、**Keep** または **Undo** を選択します。
4. たとえば、エージェントが好ましくない方法で切り替えユーザー インターフェイス (UI) をリファクタリングしようとした場合は、チャット入力欄の横にある **Stop** を選択して停止し、意図を明確にする追加メッセージを送信します。

> [!TIP]
> 実行中のセッションへの追加指示は、新しい会話を始めるよりも効率的です。「CSS を簡潔にして、selector の重複ではなく CSS 変数を使う」などの調整、「3つ目の切り替えは追加せず、既存の設定パネルにライトモードを統合する」などの方向修正、「両方の切り替えにキーボード ショートカットも追加する」などの範囲拡張を依頼できます。

## 変更されたファイルをレビューする

commit する前に、エージェントが変更したファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro component、スタイル、関連テストなどが更新されているはずです。
3. 変更したファイルをいくつか開き、差分を確認します。Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティック HyperText Markup Language (HTML)、local storage による設定の保持など、カスタムエージェントのアクセシビリティ パターンが反映されていることを確認します。
4. 内容に問題がなければ、Source Control パネルから変更を stage して commit します。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat agent mode を使い、進行中のセッションを監視して方向づけました。ファイル編集を確認して採用または却下し、コンテキストを保ったまま追加の指示を送って作業を拡張しました。

このレッスンでは、次の内容を学びました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を採用または却下する。
- 追加プロンプトで実行中のセッションを方向づける。

次のレッスンでは、アクセシビリティの作業を pull request として公開し、このラボを通じてローカル カスタムエージェントが作成した変更をレビューします。
